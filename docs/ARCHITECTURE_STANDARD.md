## اصل ۱: ساختار استاندارد هر ماژول

هر ماژول علمی/مهندسی باید این ساختار را داشته باشد:
engine/land/ # یا: engine/soil/, engine/climate/
├── init.py # Exports عمومی
├── models.py # Pydantic V2 models + Enums
├── [core_module].py # منطق اصلی
├── reference/ # داده‌های مرجع (اختیاری)
│ ├── init.py
│ ├── models.py # مدل‌های مرجع
│ └── data.py # داده‌های داخلی + توابع
├── integration/ # اتصال به سایر ماژول‌ها
│ ├── init.py
│ ├── models.py
│ └── [module]integrator.py
└── tests/ # تست‌های جامع
├── init.py
└── test[module].py # حداقل ۴ تست در هر کلاس

## اصل ۲: قوانین کدنویسی

| قانون | توضیح |
|---|---|
| **پیاده‌سازی مستقیم** | بدون واسطه‌های اضافی، مستقیم در کد اصلی |
| **بدون ورود به دیتابیس** | در این فازها فقط محاسبات خالص |
| **تست قبل از ادغام** | همه تست‌ها باید پاس شوند |
| **پوشش کد ≥ ۸۰٪** | با `pytest --cov` |
| **بدون خطای نحوی** | با `python -m py_compile` |

## اصل ۳: استاندارد تست‌ها

هر تست باید:
1. **شفاف** باشد: نام تست دقیقاً رفتار را توصیف کند
2. **مستقل** باشد: بدون وابستگی به تست‌های دیگر
3. **قابل تکرار** باشد: با `np.random.seed` یا مقادیر ثابت
4. **معنادار** باشد: بر اساس مقادیر علمی واقعی

## اصل ۴: مدیریت داده‌ها

| نوع داده | مکان |
|---|---|
| **داده‌های مرجع ثابت** | `reference/data.py` (داخل کد) |
| **داده‌های پویا** | `data/` (SQLite/JSON) |
| **کش محاسبات** | `engine/data/cache.db` |

## اصل ۵: نام‌گذاری

| عنصر | الگو | مثال |
|---|---|---|
| فایل اسکریپت فاز | `phase[شماره][حروف]_[نام].py` | `phase2a_soil_integration.py` |
| کلاس اصلی | `[مفهوم][نوع]` | `SoilIntegrator` |
| Enum | `[مفهوم]Type/Class` | `TerrainType`, `SlopeClass` |
| تابع تست | `test_[رفتار]` | `test_classify_loam` |
