> زمان تقریبی: ۱۰-۱۵ دقیقه · بدون نیاز به کدنویسی · هر دو عملیات در **SQL Editor** دشبورد Supabase انجام میشود.

## پیشنیاز

1. به https://supabase.com/dashboard بروید و وارد حساب خود شوید.
2. پروژه خود را باز کنید (همان که `SUPABASE_URL` در `.env` به آن اشاره دارد — با `cpncgg…` شروع میشود).
3. از منوی کناری **SQL Editor** را باز کنید.

## بلاکر ۱: رفع ثبتنام (خطای «Database error saving new user»)

### گام ۱.۱ — تشخیص تریگرهای auth.users
در SQL Editor یک **New query** باز کنید و این را اجرا کنید:

```sql
select tgname, pg_get_triggerdef(t.oid)
from pg_trigger t
where tgrelid = 'auth.users'::regclass
  and not tgisinternal;
```

**نتیجه را کپی کنید و برای من بفرستید.** مهمترین چیزی که دنبالش هستیم:
- تریگری مثل `on_auth_user_created` که بعد از ساخت کاربر، ردیفی در جدول دیگری (مثلاً `profiles` یا `platform_profiles`) میسازد.
- اگر آن تابع به جدول/ستونی که **وجود ندارد** ارجاع دهد، دقیقاً همین خطای 500 هنگام ثبتنام رخ میدهد.

### گام ۱.۲ — رفع (فقط اگر مطمئن هستید تریگر خراب است)
اگر در خروجی گام ۱.۱ تریگر غیراستانداردی دیدید که به جدول ناموجود ارجاع میدهد، آن را حذف کنید (نام را جایگزین کنید):

```sql
-- مثال: حذف تریگر ساخت خودکار پروفایل (نام واقعی از خروجی گام ۱.۱)
drop trigger if exists on_auth_user_created on auth.users;
```

> ⚠️ احتیاط: فقط تریگری را حذف کنید که مطمئن هستید خراب است. اگر شک دارید، **خروجی گام ۱.۱ را برای من بفرستید** تا دستور دقیق بدهم.

### گام ۱.۳ — روش جایگزین (سادهتر، توصیهشده): دادن پسورد دیتابیس به من
اگر ترجیح میدهید خودم همهچیز را انجام دهم:

1. در دشبورد: **Project Settings ← Database ← Connection string** را باز کنید.
2. در بخش «Direct connection» (یا pooler) پسورد دیتابیس را بردارید (پس از `postgres.` و قبل از `@`).
3. در فایل `D:\eco_nojin\.env` این خط را **اضافه** کنید (جای `YOUR_PASSWORD`):

```
SUPABASE_DB_PASSWORD=YOUR_PASSWORD
```

4. به من بگویید «پسورد را گذاشتم» — آنگاه با psql مستقیم وصل میشوم، تریگر را تشخیص/رفع میکنم و migration را هم خودم اجرا میکنم.

### گام ۱.۴ — تست ثبتنام
بعد از رفع، در برنامه (localhost:8011) از صفحه ثبتنام یک حساب تست بسازید، یا از من بخواهید تست را اجرا کنم. اگر پیام «لینک تأیید ارسال شد» (یا ورود موفق) دیدید، بلاکر ۱ رفع شده است.

## بلاکر ۲: اجرای migration 0001 (RLS + PostGIS + badges)

### گام ۲.۱ — باز کردن فایل migration
فایل آماده است:
`D:\eco_nojin\supabase\migrations\0001_phase6_harden.sql`

آن را با Notepad باز کنید و **کل محتوا** را کپی کنید.

### گام ۲.۲ — اجرا در SQL Editor
1. در SQL Editor یک **New query** باز کنید.
2. کل محتوای فایل را paste کنید.
3. دکمه **Run** (یا Ctrl+Enter) را بزنید.

خروجی طبیعی: `Success. No rows returned` (یا پیام مشابه) — چون همه دستورها idempotent هستند، اگر دوباره هم اجرا کنید خطا نمیدهد.

### گام ۲.۳ — تأیید اجرا (اختیاری اما توصیهشده)
همین query ها را به ترتیب اجرا کنید و نتیجه را ببینید:

```sql
-- 1) PostGIS فعال است؟
select extname, extversion from pg_extension where extname = 'postgis';

-- 2) جدول badges ساخته شده؟
select count(*) from platform_badges;

-- 3) RLS روی همه جدولهای اصلی فعال است؟
select relname, relrowsecurity
from pg_class
where relname in ('platform_landscapes','platform_profiles','platform_carbon_projects','platform_badges','users','standards')
  and relkind = 'r';
```

نتیجه مورد انتظار:
- سطر postgis با نسخه (مثلاً 3.4)
- count = 0 (جدول خالی ولی موجود)
- همه relrowsecurity = **true**

### گام ۲.۴ — چه چیزی تغییر میکند (توضیح)
- **قبل**: هر کسی (حتی بدون ورود) میتوانست همه جدولها را بخواند — ریسک امنیتی.
- **بعد**: خواندن عمومی فقط برای کاتالوگها (landscapes/standards/badges)؛ داده شخصی (پروفایل، پروژهها، اعضاییت، کاربران) فقط برای مالکِ همان ردیف (auth.uid) قابل خواندن/ویرایش است.
- اگر بعداً بخشی از برنامه خطای «دسترسی ندارید» داد، آن جریان واقعاً باید با ورود کاربر کار کند — این همان رفتار درست است.

## بعد از انجام هر دو

به من بگویید «انجام شد» (و اگر گام ۱.۱ را اجرا کردید، خروجیاش را بفرستید). من بلافاصله:
1. جریان کامل را تست میکنم: ثبتنام (با کاربر تست) ← ساخت پروژه کربن ← خواندن پروفایل ← فهرست پروژهها.
2. مطمئن میشوم RLS مالکیت را واقعاً الزامی میکند (تست با anon باید fail شود).
3. جدولهای LMS را روی Supabase میسازم و پیشرفت درسها را ابری میکنم.
4. query واقعی PostGIS (ST_DWithin) را جایگزین Haversine میکنم.
