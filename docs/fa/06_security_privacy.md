# ۰۶. امنیت و حریم خصوصی

**وضعیت:** تأیید شده | **نسخه:** ۱.۰.۰ | **زبان:** فارسی

## ۱. اصول

- **حاکمیت داده:** کشاورزان مالک داده خود هستند؛ پلتفرم امانت‌دار است.
- **ناشناس‌سازی:** داده‌های تجمیع‌شده پیش از هر استفاده بیرونی ناشناس می‌شوند.
- **کمینه‌سازی:** فقط داده لازم برای خدمت درخواستی جمع‌آوری شود.
- **آمادگی پساکوانتومی:** رابط‌ها برای الگوریتم‌های تأییدشده NIST PQC (ML-KEM برای تبادل کلید، ML-DSA برای امضا) در لایه دفتر کل و API محفوظ است.

## ۲. وضعیت فعلی (صادقانه)

| حوزه | وضعیت |
|---|---|
| امنیت انتقال | هنوز پیکربندی نشده (حالت توسعه، HTTP) — TLS برای هر استقراری الزامی است |
| احراز هویت / مجوز | **پیاده‌سازی نشده** (سرویس auth placeholder است) |
| CORS | `allow_origins=["*"]` همراه `allow_credentials=True` — ترکیب نامعتبر؛ باید با فهرست صریح origins جایگزین شود |
| اسرار (Secrets) | `.env.example` با `change_me`؛ `docker-compose.yml` حاوی رمز جایگزین `***` است — اسرار واقعی باید در vault نگهداری شوند |
| اعتبارسنجی ورودی | شِماهای Pydantic در مرز API (خوب) |
| سیاست وابستگی‌ها | `requirements.txt` بدون نسخه‌بندی — پیش از انتشار پین و ممیزی شود |
| داده در حال استراحت | دیتابیس پژوهشی SQLite رمزنگاری نشده؛ سیاست رمزنگاری/پشتیبان‌گیری PostGIS تولید لازم است |
| یکپارچگی MRV | هش‌کردن رکوردهای MRV در لایه دفتر کل برنامه‌ریزی شده (فاز ۵) |

## ۳. نکات برجسته مدل تهدید

- **در معرض بودن API بدون محافظ:** استقرار دروازه امروز، اندپوینت‌های نوشتاری بدون احراز هویت (سفارش بازارچه، ثبت پروژه کربن، sync) را باز می‌گذارد — فقط در شبکه‌های پژوهشی مورد اعتماد قابل قبول است.
- **داده ماهواره‌ای شبیه‌سازی‌شده:** هرگز نباید به‌عنوان مشاهده واقعی به ذی‌نفعان بیرونی ارائه شود (ریسک یکپارچگی داده؛ رجوع `02_hydroma_engine.md`).
- **اندپوینت تأیید کربن:** فقط دموی داخلی؛ ارائه خروجی آن به‌عنوان اعتبار گواهی‌شده خطر نظارتی/کلاهبرداری است.

## ۴. کنترل‌های هدف (نقشه راه)

۱. سرویس احراز هویت/مجوز (OAuth2/OIDC با نقش‌های کشاورز، تعاونی، NGO، مدیر).
۲. فهرست CORS صریح؛ HTTPS در همه‌جا؛ HSTS.
۳. مدیریت اسرار (vault محیطی / سرویس ابری).
۴. وابستگی‌های پین‌شده و ممیزی‌شده؛ اسکن وابستگی در CI.
۵. تفکیک داده هر مستأجر و سوابق رضایت برای اشتراک‌گذاری داده.
۶. مدیریت کلید آماده PQC در لایه دفتر کل (رابط‌های ML-KEM/ML-DSA).
۷. لاگ ممیزی داده‌های MRV با هش رمزنگاری (اثبات دستکاری‌نشدن).

## ۵. حریم خصوصی در طراحی

- داده موقعیت (قلاب‌های geolocation در فرانت‌اند) فقط برای تحلیل درخواستی استفاده می‌شود و به‌صورت پیش‌فرض به اشتراک گذاشته نمی‌شود.
- جریان‌های USSD/SMS تبادل داده را کمینه می‌کنند؛ شماره تلفن داده شخصی محسوب می‌شود.
- سرمایه‌گذاران اثرگذار فقط معیارهای ناشناس و تجمیع‌شده می‌بینند.

## ۶. پاسخ به حادثه (برنامه‌ریزی‌شده)

پیش از اولین پایلوت عمومی، runbook (سطوح شدت، مخاطبین، تعهدات اطلاع‌رسانی نقض داده طبق صلاحیت‌های مربوطه) تهیه شود.
