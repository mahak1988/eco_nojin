# برنامه توسعه اجرایی اکو نوژین و HyDroMa

نسخه: 1.0
تاریخ شروع: 21 اوت 2026
شاخه هدف: main
وضعیت: فاز صفر در حال اجرا

## هدف نزدیک

هدف سه ماه اول، تبدیل MVP گسترده فعلی به یک مسیر قابل اعتماد برای پایلوت است:

ثبت مزرعه → تحلیل خاک/آب/اقلیم → توصیه عملی → ثبت نتیجه → گزارش قابل ردیابی

تا زمان تثبیت این مسیر، توسعه قابلیت‌های مالی، بیمه، اعتبار کربن و بلاکچین در اولویت دوم قرار می‌گیرد.

## فاز صفر: تثبیت و ممیزی فنی

مدت: 1 تا 2 هفته

- اجرای backend و frontend از محیط تمیز و ثبت نتیجه واقعی تست‌ها
- اصلاح CORS، dependencyها، secretهای نمونه و CI
- بررسی health/readiness و migrationهای پایگاه داده
- تعیین وضعیت هر endpoint: واقعی، آزمایشی یا شبیه‌سازی‌شده
- حفظ برچسب صریح simulated برای داده‌های ماهواره‌ای غیرواقعی
- تکمیل کنترل دسترسی تمام مسیرهای write و ثبت audit log

خروجی پذیرش: اجرای reproducible، CI سبز، بدون secret در repository و فهرست روشن قابلیت‌های production-ready.

## فاز یک: هویت و مدل داده

مدت: هفته 3 تا 5

- احراز هویت، نقش‌ها و مجوزهای farmer، agronomist، verifier و admin
- مدل‌های User، Organization/Landscape، Farm/Parcel، Observation و Recommendation
- PostgreSQL برای production و RLS برای جداسازی داده‌ها
- شناسه و audit trail برای هر تحلیل
- قراردادهای versioned برای API و schemaهای Pydantic

## فاز دو: پایلوت کشاورزی

مدت: هفته 6 تا 9

- ثبت قطعه روی نقشه
- دریافت داده اقلیم، خاک و ماهواره با provenance
- اجرای تحلیل و نمایش uncertainty، تاریخ داده و فرضیات مدل
- توصیه‌های آبیاری، مدیریت خاک و احیا
- داشبورد روند تغییرات و ثبت نتیجه اقدام کشاورز

داده مصنوعی نباید به‌عنوان مشاهده واقعی نمایش داده شود یا وارد محاسبه MRV و کربن شود.

## فاز سه: اعتبار علمی و MRV

مدت: هفته 10 تا 14

- model registry و نسخه‌بندی پارامترها
- ذخیره input/output، نسخه کد، زمان اجرا و uncertainty
- calibration محلی و quality gate
- چرخه پروژه کربن از draft تا verified و retired
- گزارش MRV قابل بازتولید و قابل بازبینی انسانی

## فاز چهار: مالی و بیمه

پس از موفقیت پایلوت: امتیازدهی توضیح‌پذیر، ثبت وام، بیمه شاخص‌محور، شبیه‌سازی claim و سپس اتصال پرداخت.

## فاز پنج: مقیاس

پس از اثبات ارزش: multi-tenancy، صف کار، object storage، observability، IoT، localization منطقه‌ای و adapter بلاکچین.

## معیارهای موفقیت 90 روزه

- 20 مزرعه پایلوت
- حداقل 95٪ تحلیل‌های موفق یا دارای خطای قابل توضیح
- صفر نمایش داده مصنوعی به‌عنوان مشاهده واقعی
- احراز هویت و audit برای تمام عملیات write
- وجود source، timestamp، model version و uncertainty در خروجی علمی
- حداقل یک گزارش MRV قابل بازتولید

## قواعد اجرایی

1. هر فاز با تست و معیار پذیرش تمام می‌شود.
2. تغییرات بزرگ در commitهای کوچک و قابل بازگشت ثبت می‌شوند.
3. سرویس‌ها تا قبل از نیاز عملیاتی به microservice جدا تبدیل نمی‌شوند؛ modular monolith ترجیح دارد.
4. blockchain در adapter باقی می‌ماند و منطق domain به آن وابسته نمی‌شود.
5. هیچ ادعای استاندارد یا علمی بدون منبع، نسخه مدل و مسیر محاسبه منتشر نمی‌شود.
