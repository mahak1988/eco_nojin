# عوامل پایدار (Persistent Agents) — راهنمای اجرا

این پوشه «دستور عملیاتی» پنج عامل است. هر عامل یک job زمان‌بندی‌شده است که به‌صورت تکرارشونده در یک نشست ایزوله اجرا می‌شود و **هر بار فقط یک واحد کار** را جلو می‌برد.

## چرا این معماری؟

| گزینه | مشکل |
|---|---|
| اجرای موازی ۵ عاملِ طولانی روی یک مخزن | تضاد فایل و کار نیمه‌کاره |
| وعدهٔ «عامل همیشه‌فعال» | در این پلتفرم وجود ندارد؛ job زمان‌بندی‌شده نزدیک‌ترین معادل پایدار است |

## قواعد مشترک (در همهٔ دستورها تکرار شده)

- هیچ **دادهٔ ساختگی** وارد نشود؛ در نبود داده، «حالت خالی صادقانه».
- هیچ سروری روی پورت‌های ۳۰۰۰/۳۰۰۱/۳۱۱۱ اجرا نشود.
- `pnpm install` اجرا نشود (وابستگی‌ها موجود است).
- هر عامل فقط در دامنهٔ فایل خودش می‌نویسد؛ پنجره‌های دقیقاً جدا هستند.
- در قطعی شبکه یا نبود دروازه، کار به واحد بعدی منتقل می‌شود و در فایل وضعیت با کلید `blocked` ثبت می‌گردد؛ اجرای بعدی خودش ادامه می‌دهد.

## فایل‌های وضعیت

- `state/agent-1.json` … `state/agent-5.json` — پیشرفت هر عامل
- `STATE_OF_WORK.md` — تصویر جمعی (ناظر می‌نویسد)
- `AGENTS_LOG.md` — یک خط در هر اجرای ناظر (روند تاریخی)

## اجرای دستی

```
cron list                 # برای دیدن jobها
cron run <jobId>          # اجرای فوری یک عامل
cron runs <jobId>         # تاریخچهٔ اجراها
```

## محدودیت‌ها (صادقانه)

1. jobها فقط وقتی Gateway فعال است اجرا می‌شوند؛ اگر ماشین خاموش باشد، اجرا به نوبت بعدی موکول می‌شود (وضعیت در فایل‌ها از دست نمی‌رود).
2. اعلان مستقیم در WebChat برای cron پشتیبانی نمی‌شود؛ گزارش‌ها در فایل‌های بالا نوشته می‌شوند و هر زمان می‌توانید از Agent بخواهید خلاصه بدهد.
3. سرعت پیشرفت هر اجرا یک واحد است؛ برای تسریع، فاصلهٔ زمانی jobها کوتاه شود (مثلاً هر ۱ ساعت).
