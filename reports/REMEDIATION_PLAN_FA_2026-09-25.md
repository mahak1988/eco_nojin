## ۴. موج ۲ — استانداردسازی فرمول‌ها (محور اصلی درخواست)

**این مهم‌ترین موج برای دوام علمی پروژه است.** مسئله: همان کمیت فیزیکی در چند فایل با معادلات متفاوت محاسبه می‌شود و هیچ سازوکاری برای داوری وجود ندارد.

### ۴.۱ دفترچهٔ فرمول (Formula Registry)

ساختار جدید `engine/hydroma/formulas/`:

```
formulas/
├── registry.py          # ثبت و بازیابی؛ منبع حقیقت واحد
├── records.py           # ساختار ثبت هر فرمول
├── reference/           # مقادیر مرجع منتشرشده
│   ├── fao56_et0.yaml
│   ├── rothc_yields.yaml
│   ├── penman_monteith.yaml
│   └── ... (10 YAML موجود + 15 npy منتقل می‌شوند)
└── implementations/     # یک ماژول = یک کمیت
    ├── et0_reference.py
    ├── soil_water_balance.py
    ├── erosion.py
    ├── carbon_decomposition.py
    └── canopy_indices.py
```

هر ثبت (`records.py`) این فیلدها را دارد:

| فیلد | نمونه | چرا لازم است |
|---|---|---|
| `quantity` | `et0_reference` | شناسهٔ یکتا؛ نام‌های هم‌معنا ممنوع |
| `canonical` | `formulas/implementations/et0_reference.py` | تنها محل مجاز پیاده‌سازی |
| `literature_ref` | `FAO-56, eq. 6, ch.3` | مرجع، نه «یک مقاله» |
| `units` | `mm/day` | بدون واحد، مقایسه بی‌معناست |
| `domain` | `scalar | array` | تعیین‌کنندهٔ انتخاب backend |
| `backend_priority` | `[numpy, numba, cpp]` | ترتیب **بر اساس اندازهٔ ورودی** |
| `parity_tests` | `["test_et0_fao56_table", ...]` | بدون آزمون ⇒ ثبت نامعتبر |
| `reference_values` | مسیر YAML | لنگر عددی |
| `status` | `verified \| divergent \| stub` | صراحت در وضعیت |
| `backends_impl` | `{numpy: ✅, numba: ❌, cpp: ⚠️}` | دیده‌شدن شکاف |

### ۴.۲ قواعد سخت (Non-negotiable)

1. **هیچ فرمولی خارج از `formulas/` پیاده نشود.** هر فرمول جدید یا مهاجرت می‌کند یا ثبت می‌شود.
2. **بدون `parity_tests`، ثبت نامعتبر است.** فرمول بدون آزمون تطابق، کد بدون اثبات است.
3. **`status: divergent` ممنوع در مسیر تولید.** یعنی اگر دو backend عدد متفاوت بدهند، آن backend از مسیر خارج می‌شود تا رفع شود.
4. **هر مقدار `0.0` مشکوک است.** هیچ فرمولی نباید به‌خاموشی `0.0` برگرداند. الگوی فعلی `except Exception: return 0.0` در `formula_evaluator.py:145-148` و `calculation_engine.py:61-62` **ممنوع** است — به‌جای آن یک نوع خطای صریح.
5. **هر backend باید به مقادیر مرجع منتشرشده در جدول FAO/IPCC بخورد**، نه به پیاده‌سازی دیگر. تطابق با دیگری دایرهٔ کامل است.

اگر یک نفر هستید، این ترتیب بیشترین اثر با کمترین ریسک را دارد:

1. **موج ۰.۱ + ۰.۲** (بنچمارک پایه + فعال‌سازی آزمون‌های تطابق) — ۳ روز
