# R18 baseline

Recorded engine outputs, used to make the blast radius of an equation change
attributable.

## Why

Phase 3 of the integration plan changes equations. Each change is individually
justified by a standard, but the blast radius is not obvious. Changing
`FC_HEAD_CM` from 330 to 33 moves plant-available water, which moves leaching,
which moves the crop water requirement, which moves the irrigation schedule.
Six modules move because one line moved.

Without a recorded "before", an intended correction and an accidental side
effect look identical. This is Decision 7 (no double counting) applied to code.

## What it does not do

It does not assert the engine is correct. Several recorded values are known
wrong:

| Recorded value | Defect |
|---|---|
| `soil_retention.awc_cm3_cm3.sand` = 0.00058 | field capacity evaluated at −330 cm, so 99.4 % under-reported |
| `carbon.biochar_temperate_100ha_10y.annual_rate_tonnes` = 3000 | area applied twice; correct value is 25.5 |
| `watershed_design.check_dam.a50000000_s50.storage_required_m3` = 1 786 179 | dam height clamped to 6 m, so `dam_volume_m3` is 840 — a 2 127× shortfall reported in the same dict |
| `watershed_design.terrace.s2.0_a200.erosion_reduction_pct` = −177 | no lower bound on the reduction |
| `watershed_network.muskingum.K1.0_x0.2_dt10.0[6]` = −0.743 | negative discharge; the stability check is vacuous |

The state is frozen on purpose. The correction commits of Phase 3 are then
readable one field at a time instead of arriving as one unreviewable wave.

## Commands

```bash
python -m engine.baseline.capture --show        # print the live capture
python -m engine.baseline.capture --diff        # per-field report
python -m engine.baseline.capture --diff --quiet # one-line summary, for CI
python -m engine.baseline.capture --regenerate  # rewrite R18.json
```

## Rules

1. `--regenerate` is a separate verb, not a flag on `--diff`, so a
   stale-baseline failure can never quietly rewrite itself.
2. A regenerated baseline must name the governing standard in its commit
   message, citing a chapter and table rather than a line number, per the
   project's reference rule.
3. Removing a case is a decision, not a cleanup. It removes the ability to
   attribute a future change to whatever that case was witnessing.
4. No expected value is authored by hand anywhere in this package. The baseline
   is generated by running the engine, so it records state rather than
   asserting correctness. `test_s00_baseline.py` enforces this.

## Case selection

Defined in `cases.py`. Four rules:

1. **Deterministic** — no timestamps, no UUIDs, no network, no rasters.
2. **Defect-sensitive** — every case is chosen so a known pending correction
   moves it. A case insensitive to the fix is dead weight.
3. **Physically meaningful** — inputs sit inside the range the function serves.
4. **Cheap** — the whole capture runs in under a second.

Current coverage: 13 cases, 3 495 recorded values, across soil retention,
climate ET0, runoff, watershed design, watershed network, groundwater, carbon,
irrigation, salinity, remote-sensing indices, terrain and erosion.

Two known gaps, deliberate:

- **Spatial runoff** is not recorded. `SpatialRunoffCalculator.execute` needs
  three rasters on disk and `rioxarray`, so it cannot run in a capture. The
  curve-number map defect is witnessed instead by the scalar cases plus the
  S03 tripwire on `_create_cn_map_from_lu_soil`.
- **RothC and ECSI** are not recorded. The engine already has dedicated
  reference-value tests with the Broadbalk anchor, so a second baseline would
  duplicate them without adding attribution.

## Non-finite values

Edge cells of a slope or aspect grid legitimately produce `NaN`. These are
written as the JSON strings `"NaN"`, `"Infinity"`, `"-Infinity"` rather than
the bare literals, because `json.dump` would otherwise emit `NaN`, which is
**not valid JSON** and is rejected by strict parsers in other tools.
