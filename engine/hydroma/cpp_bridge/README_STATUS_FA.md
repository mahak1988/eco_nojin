# پل C++ و موتور عددی — وضع موجود
## `engine/hydroma/cpp_bridge/`

سند توصیف وضع موجود. هر ادعا با اجرای کد در همین مخزن راستی‌آزمایی شده است.

---

## ۱. اجزای بسته

پس از حذف جفت‌های تکراری، بسته چهار فایل دارد:

| فایل | نقش |
|---|---|
| `__init__.py` | بارگذاری، گزینش backend، telemetry |
| `indices_fast.py` | هسته‌های Numba برای NDVI/EVI/SAVI/NBR |
| `hydrology_fast.py` | هسته‌های Numba برای مسیریابی سیل |
| `soil_physics_fast.py` | هسته‌های Numba برای فیزیک خاک |

نام‌های `*_fallback` حذف شدند. هر سه جفت فایل **با MD5 یکسان** بودند — یعنی
«fallback» و «fast» یک فایل واحد بودند و هیچ C++‌ای در آن‌ها نبود.

تنها مصرف‌کنندهٔ `indices_fallback` در درخت اصلی
`engine/hydroma/simulation_env/stress.py` بود که به `indices_fast` تغییر کرد.

## ۲. بارگذاری

**یک بارگذار وجود دارد:** `cpp_bridge/__init__.py`. مسیر پوشه به `sys.path` افزوده
و `import hydroma_core` انجام می‌شود، با محافظت `sys.modules.setdefault` در برابر
بارگذاری دوباره.

`engine/hydroma/cpp_bindings.py` بارگذاری مستقل نیست؛ یک لایهٔ واگذار به
`cpp_bridge` است.

### بارگذارهای حذف‌شده

دو بارگذار دیگر وجود داشت و هر دو حذف شدند:

| بارگذار حذف‌شده | چرا حذف شد |
|---|---|
| `engine/hydroma/cpp_bindings.py` (نسخهٔ قبلی) | همان ماژول را با `spec_from_file_location` دوباره اجرا می‌کرد که pybind11 با `generic_type: type "..." is already registered!` رد می‌کند. fallback بدون احراز ABI هم داشت: هر فایلی که نامش با `hydroma_core` شروع می‌شد پذیرفته می‌شد |
| `services/models/cpp_bridge.py` | بارگذار **ctypes** برای یک `.dll` با ABI نوع C. فایل `.dll` در هیچ‌جای مخزن وجود نداشت، منبعش (`bindings/c_api.cpp`) در هیچ هدف CMake نبود، و سه تابعش صفر فراخوانی داشتند. تنها چیزی که از آن import می‌شد `status()` بود که `/api/v1/models/cpp-status` را تغذیه می‌کرد |

تناقضی که حذف دوم برطرف کرد: `/health` از ماژول pybind11 می‌خواند و
`cpp_core: "ok"` می‌داد، در حالی که `/api/v1/models/cpp-status` همیشه
`available: false` می‌داد. هر دو endpoint اکنون از
`engine.hydroma.cpp_bridge.backend_status()` می‌خوانند.

### اگر روزی مصرف‌کنندهٔ غیرپایتونی لازم شد

آن زمان سطح C معنادار است و مراحل لازم:

1. `c_api.cpp` را دوباره بسازید و **به `CMakeLists.txt` اضافه کنید** — بدون آن
   در هیچ مسیر ساختی نیست.
2. `vg_theta` را **واگذار** کنید به توابع `soil.cpp`، نه بازنویسی. نسخهٔ قبلی فرمول
   van Genuchten را موازی `soil.cpp` تعریف می‌کرد و کمیت واحد را چهار بار پیاده
   می‌ساخت.
3. یک بارگذار را انتخاب کنید. دو بارگذار برای یک artifact، بدهی فنی است.

`backend_status()` گزارش وضعیت را برمی‌گرداند.

## ۳. گزینش backend

```
آرگومان اسکالر    →  C++  →  NumPy
آرگومان آرایه     →  Numba (N < 1_000_000)  →  C++  →  NumPy
```

`_ARRAY_CPP_THRESHOLD` = ۱٬۰۰۰٬۰۰۰ عنصر. دلیل عددی در
`engine/cpp_core/README_BUILD_STATUS_FA.md` بخش ۵ آمده است.

هر سه مسیر یک عبارت را محاسبه می‌کنند؛ اختلاف عددی صفر اندازه‌گیری شده است.

## ۴. رتبه‌بندی ورودی

`indices_fast.py` ورودی ۱بعدی و ۲بعدی را می‌پذیرد و رتبهٔ خروجی را حفظ می‌کند.
پیش از این تغییر، هسته‌ها `rows, cols = arr.shape` را باز می‌کردند و ورودی
۱بعدی — شکل معمول یک سری زمانی بازتاب ماهواره‌ای — با `TypingError` رد می‌شد.
ورودی سه‌بعدی با پیام روشن `ValueError` رد می‌شود.

## ۵. telemetry

سه شمارنده: `numba_calls`، `cpp_calls`، `fallback_calls` و مجموع زمان هرکدام.
`reset_telemetry()` همه را صفر می‌کند.

افزایش شمارنده‌ها روی دیکشنری سراسری و بدون قفل انجام می‌شود. این مسیر از
threadpool استارلِت در فراخوانی می‌شود، پس شمارش زیر بار همزمان می‌تواند
گم شود.

## ۶. آنچه بدون C++ رخ می‌دهد

طبق `cpp_bridge/__init__.py`، ۴۶ نماد به `_py_not_implemented` وصل‌اند و
`NotImplementedError` می‌دهند. هر فراخوانی که در مسیر C++ استثنا بدهد — از جمله
یک نقص واقعی در C++ — بی‌صدا به Python برمی‌گردد و در `fallback_calls` شمرده
می‌شود. یعنی telemetry نمی‌تواند «C++ موجود نیست» را از «C++ غلط است» تفکیک کند.
این رفتار در این کار تغییر نکرد.

## ۷. وضعیت گزینش‌پذیری

| وضعیت | نتیجه |
|---|---|
| C++ موجود + Numba موجود | گزینش بر پایهٔ اندازه |
| C++ موجود، Numba نیست | همهٔ آرایه‌ها → C++ |
| C++ نیست، Numba هست | آرایه → Numba، اسکالر → NumPy |
| هیچ‌کدام نیست | همه → NumPy |

## ۸. آنچه اندازه‌گیری نشده

- بدهی بافر/کارایی: هیچ اندازه‌گیری حافظه‌ای ثبت نشده است.
- مقیاس‌پذیری چندنخی: `total_*_time_ms` شمارنده است، نه تحلیل. هیچ آزمون همزمانی
  وجود ندارد.
- پرچم `/openmp:llvm` واقعاً موازی‌سازی می‌کند یا فقط پذیرفته می‌شود: تأیید
  نشده است. اثبات آن نیازمند دو اجرای مقایسه‌ای با و بدون پرچم است.
